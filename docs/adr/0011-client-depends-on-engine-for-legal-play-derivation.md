# Client depends on @skull-king/engine for legal-play derivation

The follow-suit rule that decides which cards a Player may legally play lived only inline inside the server-side `playCard` command handler. The client's view-model layer needs the same rule to tell a Player which cards are playable before they commit (issue #1, story 26). Rather than re-implementing a second copy of the rule in the client (risking drift if the rule ever changes, e.g. how Tigress-as-Escape interacts with follow-suit), the check is extracted into an exported `legalPlays(hand, currentTrick)` helper in the engine, and the client adds `@skull-king/engine` as a direct dependency to reuse it. This is safe because the engine is already a pure, dependency-free TypeScript module with no sockets, persistence, or React — nothing about it is server-only, that was just an accident of which package happened to import it first.
