# Round-score history lives in RoomState, not a broadcast domain-event channel

The engine already computes a rich per-Round score breakdown (`RoundScore`/`RascalRoundScore` — bid hit/miss, Outcome, Bonus, Alliance payout) and pushes it as a `RoundScoredEvent`, but the Realtime Server only ever broadcasts `roomState` to clients, never `result.events`. The client needs that breakdown for a detailed Scoreboard (matching the physical game's scoresheet). Rather than adding a second `roomEvent` broadcast channel — with its own ordering, replay-on-reconnect, and redaction concerns — `RoomState` gains a `roundScores` field that accumulates every scored Round's breakdown, populated at the same place `trickPlay.ts` already builds the scores. It rides the existing `roomState` broadcast and existing persistence, at the cost of the wire state growing by one array entry per Round (bounded at 10) for the life of a Game.
