# A `hasBid` flag was added to `Player` so the client can render "has bid" without leaking values

The Bidding screen needs to show which Players have bid before the reveal (per CONTEXT.md's Bid glossary entry: hidden until everyone's in, then revealed simultaneously). `redactRoomStateFor` already nulls out every other Player's `bid` until `areAllBidsSubmitted`, but that means "hasn't bid yet" and "has bid, still hidden" were indistinguishable on the wire — both showed up as `bid: null`. Rather than have the client infer bidding progress some other way (e.g. a derived count broadcast separately), `Player` gains a `hasBid: boolean` field that always reflects the true submission state, set alongside `bid` everywhere the engine assigns or resets it (`createRoom`, `joinRoom`, `roundAdvance`, `submitBid`). Redaction never hides it — only the `bid` value itself is redacted — so the Bidding view model can show per-Player "has bid" status pre-reveal and the real values post-reveal from the same field.
